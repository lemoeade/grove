# Workspaces, settings, sessions and the state file

[← Architecture overview](../architecture.md)

Where workspaces come from, where settings and sessions are stored, and the format and migrations of state.json.

## Workspaces, settings, sessions and the state file

### Workspaces

A workspace is either a `.code-workspace` file (each entry in `folders` is a repository) or a folder.

- When a folder is opened, if it is inside a git repository, that repository is used; otherwise the folders one level down are
  scanned for git repositories (skipping folders whose names start with a dot). If no repository is found, the folder is treated
  as a plain folder (`Repo.Plain`; see the plain-folder section of [Git](git.md)).
- Repositories added temporarily outside the workspace, and hidden repositories, are recorded in the session's `added` /
  `hidden`; the workspace file is not changed.

#### Empty windows and recent workspaces

With no workspace, an empty window is shown with recent workspaces and entry points for opening a folder and cloning; the terminal
starts in the home folder (`a.home`, which is not in the repository list).

`RecentWs` holds at most 10 recent workspaces (`MaxRecentWs`). The `.code-workspace` files among them are also handed to the
system's recent items (`AddRecentDocument`); folders are not (a folder opened from the Dock's recent items would be treated as
"add a repository"), and with `WORKBENCH_STATE` set nothing is handed over at all (`OnRecent` in `cmd/workbench/main.go`).

#### Changing workspaces

`OpenWorkspace` (`app/workspaces.go`):

- If it's the current workspace: show "Workspace … is already open" and do nothing.
- If it's already open in another window: bring that window forward; this window doesn't change.
- Otherwise `RequestLeave` checks, in order, for unsaved files (`LeaveDirty`), running git write commands (`LeaveWrites`) and
  programs running in terminals (`LeaveJobs`, asked only when changing workspaces; closing a window or quitting just closes the
  terminals), asks for confirmation where needed, and only then calls `switchTo`. If the new workspace can't be opened, an error
  is shown, the current workspace stays as it is, and the new one is removed from `RecentWs`.

"Open in New Window" calls `Open` of the window registry (see the multiple-windows section of [app.md](app.md)).

#### files.exclude

`app/exclude.go`. Patterns from three places are merged:

- `settings` in the `.code-workspace` (`workspace.LoadSettings`, JSONC);
- each repository's `.vscode/settings.json` (`workspace.LoadFolderSettings`);
- "Hidden files" on the "File Tree" page of the settings (`Settings.Exclude`, comma-separated globs).

`repoExclude` compiles them into one `globs.Set` per repository, evaluated from the repository root following VS Code's rules.
Excluded files don't appear in the file tree, ⌘P, full-text search or `#`; the Git sidebar still lists their changes as usual.

- The workspace file usually isn't inside any repository and isn't watched, so `checkWsSettings` checks whether it changed when you
  switch back to the window and on ⌘R.
- A repository's `.vscode/settings.json` is reread with incremental refreshes when it changes.
- For "Hidden files" in the settings, the file tree is reloaded only after typing stops for `ExcludeDelay` (600 ms).

### Settings

`workspace.Settings` holds the options from the settings window and is shared by all windows in the process. After a change,
`SettingsChanged` syncs the settings to every window, and `app/settings.go` applies fonts, theme, material, zoom, terminal options
and so on.

Settings can be changed in three ways, all of which end up updating the same `Settings`.

#### The settings window

`ui/settings.go`, a second `mygo.Window` that shares the `App` that opened it.

- Each option is one row in the `settingRow` table; the search box in the top-right corner filters by name and description
  (`settingsResults`).
- A page is split into blocks by `settingsGroups` (page number + name of the first option in the block → subheading);
  `settingsCards` draws each block as a rounded card, with a thin line between rows (`settingsSep`).
- A row is a `settingField`: name and description on the left, control on the right. Inside fn, the control recorded by
  `settingControl` gets `LabelledBy` the name and `DescribedBy` the description (clicking the name is the same as clicking the
  control, and screen readers can read it).
- The text field inside `wui.NumberInput` can't be reached from outside, so numeric options use a hand-built `numberBox`.
- "Material" is drawn only when the window backdrop is Translucent, indented by 18.

#### The settings document

The `settings.json` tab in the editor area (`docs.SettingsDoc`, in memory only).

- Its content is every key generated by `SettingsJSON` (zero values included); ⌘S applies the settings and writes no file.
- `ParseSettings` parses strictly: an unknown key or a wrong type is reported with line and column via `SettingsError` and no
  setting is changed; once it passes, `Clamp` runs and the settings are replaced as a whole and applied to all windows.
- When the settings are changed from elsewhere, settings documents that haven't been edited are regenerated by
  `syncSettingsDocs`, so saving a stale document doesn't overwrite the newer settings.

#### Export / import / restore defaults

An export is `{"workbench": version, "exported": time, "settings": {every key}}`; on import, the keys that would change are listed
(`ChangedKeys` / `SettingNames`) for confirmation.

### Sessions

`workspace.Session` is keyed by the absolute path of the workspace file and records: open tabs (at most 50), the current tab, the
current repository, expanded repositories and folders, the collapsed / expanded state of each section and group in the Git
sidebar, terminal tabs and splits, the editor group layout, the repositories whose worktree block is expanded, and panel
visibility. It is saved when switching away, closing the window or quitting, and read back when the workspace is opened.

Some details of saving:

- Historical-version and Diff tabs are recorded too, with `path` set to the repository root (a relative path would be dropped on
  read) and the actual file in `change`; if that commit no longer exists (`GoneCommit`), the tab isn't restored.
- An encoding, language or indentation the user picked for a tab is recorded in `Tab.Enc` / `Tab.Lang` / `Tab.Indent`; line
  endings are not. Tabs viewed as hex record `hex`; a mirror of the same file opened again in another group records `copy` (which
  copy it is), and on reopen, the second occurrence of the same path is attached as a mirror of the earlier one.
- Terminal tabs record only name, folder, profile and splits, plus the background session id (see [Terminal](terminal.md)). Nothing
  is recorded when there is just one unrenamed terminal at the repository root. Terminal tabs open in the editor area (`kind` is
  `term`) are matched up by `termNum`.

### State folder

The default is `~/Library/Application Support/Grove/`; with `WORKBENCH_STATE=<dir>` that folder is used instead (tests and running
several copies rely on this). It contains:

| File | Contents |
|---|---|
| `state.json` | Settings, sessions, recent workspaces, windows open at quit; see below |
| `window-state.json` | Position and size of each window (`WindowStates`, keyed by `StateKey`), read before `mygo.App.Run` |
| `keybindings.json` | Custom shortcuts |
| `history/` | Local history |
| `termhist/` | Output replayed when terminals are reopened |
| `snippets/` | User code snippets |
| `termd.sock` | Socket of the terminal background process |

Logs are not here but in `~/Library/Logs/Grove/` (changeable with `WORKBENCH_LOGS`): `workbench.log` (renamed to
`workbench.old.log` at startup when over 1 MB), `termd.log`, and crash logs `crash-*.log` (see the startup section of
[app.md](app.md)).

#### What some keys mean

- `appVersion`: the app version used last time; when starting a different version, the status bar mentions it.
- The top-level layout keys (`sidebar` … `openEditorsFolded`) belong to the most recently saved window and are used for workspaces
  with no recorded layout and for empty workspaces; each workspace's own layout is in the session's `panels` (copied in by
  `State.Panels()`, and poured back into the top level by `SetPanels` when the workspace is opened / switched to).
- A few lists shared by all windows, most recent first:
  - `recent`: recently opened files, at most 50;
  - `commitMsgs`: commit message history, at most 30;
  - `searchHistory`: recent searches along with their toggles and include / exclude, at most 20 (older versions recorded only the
    text, under the key `searches`, which is migrated on read);
  - `taskHistory`: at most 20;
  - `recentWs`: at most 10.
- `windows`: the workspaces of the windows open at quit (by slot; an empty workspace is `""`), reopened one by one at the next
  startup; not recorded when there is only one window and it shows the most recent workspace.
- Top-level `added` / `hidden` come from older versions (not per workspace) and are empty when saved; when read, they are assigned
  to the first workspace opened. They now live in the session.
- In the session:
  - `layout` is the editor group split tree (leaves record tab indexes), not recorded when there is only one group;
  - `terms` is not recorded when there is just one unrenamed terminal at the repository root;
  - entries in `tabs` with `kind` `term` are terminals open in the editor area, matched by `termNum` to the entry in `terms` with
    the same `num`.

#### Compatibility rules

**New fields** always use `omitempty`; fields missing from old files take their default values, and unknown fields are ignored on
read (Go's JSON decoder does this by default). Adding fields doesn't bump the format version, so older versions of the app can
still read new files; they just don't use the new content. Keys not set in `settings` are not written.

**Switches that are on by default are stored inverted**, with `no` or `No` in the key name, so the default state writes nothing:

- top-level `histNoGraph`;
- in settings: `noDiagrams`, `noRemoteImages`, `noPreviewScrollSync`, `noEditorScrollSync`, `noStickyScroll`, `noWordComplete`,
  `noHoverDefinition`, `noLocalHistory`, `treeNoFollow`, `treeNoCompact`, `treeNoGuides`, `treeNoStatusColors`;
- plus `treeIconsPlain`, colored by default and stored inverted.

The old positive, default-off `treeStatusColors` is recognized by `legacyTreeColors` (a stored false is read as
`treeNoStatusColors`); the old `softWrap` switch is read by `legacySoftWrap` as `wrap: "all"`.

**`clamp` cleans up data on read**, dropping only what it can't make sense of and keeping valid data as is:

- Empty session keys and `null` sessions are dropped.
- Relative paths where absolute paths are expected are dropped: `recentWs`, `recent`, `windows` (`""` is kept), the repository in
  `taskHistory`, `added` / `hidden`; in sessions, `path`, `repo` (cleared), `open` and `wtOpen` of `tabs`, the repository-root keys
  of `dirs` / `git` / `groups` / `terms`, a terminal tab's `dir` (the whole tab is dropped) and a split pane's `dir` (cleared).
  Folders in `dirs` are paths within the repository, so absolute ones are dropped; `git` accepts only `open` / `closed`.
- Deduplicate and truncate to the limits: `recentWs` 10, `recent` 50, `commitMsgs` 30 (empty ones dropped), `searchHistory` 20
  (entries without text dropped), `taskHistory` 20 (commands containing newlines dropped), `windows` 100, session `tabs` 50 (with
  negative line, column or scroll dropped), 20 terminal tabs per repository. A split tree that is malformed or has more than 8 panes
  is discarded entirely, an invalid ratio becomes one half, and a `hist` that isn't a `.vt` file name is cleared.
- Out-of-range indexes: a session's `active` goes back to -1, a terminal's `active` to 0.
- Layout (`clampPanels`): an unknown sidebar mode goes back to files (`files` / `search` / `git` / `outline` are accepted); widths
  and heights out of range go back to their defaults: `sidebarW` 160–800, `rightW` 200–900, `bottomH` 80–1200, `termW` 240–1200.
- Settings (`Settings.Clamp`, also run when saving the settings document and on import):
  - Options not in their list of allowed values (theme, style, window backdrop, material, accent color, indentation, wrapping,
    whitespace, auto save, terminal position, pull mode, language) go back to the default; an accent color set to the default one
    is stored as `""`.
  - Terminal theme names containing control characters or that are too long are cleared.
  - Numbers out of range go back to the default (stored as 0): editor / terminal font size 9–32, scrollback 0–1000, zoom `zoom`
    50–300, overlay opacity `frostOpacity` 50–100; local history days `historyDays` accepts only the allowed steps (7 / 30 / 90 /
    365). Zoom, opacity and days that equal the default (100 for zoom) are also stored as 0.
  - Unusable terminal profiles (`Profiles`) are dropped; web host entries with an unknown kind or a host name longer than 255
    bytes are dropped.

**The format version** is bumped only when the meaning of a field changes. It is currently 5; the latest change was the meaning of
an unset `settings.lang`: from version 5 the UI defaults to English, so a missing `lang` means "not chosen" and resolves through
`i18n.Default` (set to `"en"` by `cmd/workbench`), while `"zh"` / `"en"` are explicit choices. Files older than version 5 that
have no `lang` were Chinese, so `LoadState` writes `"zh"` into them on read and existing users stay on Chinese
(`TestStateLangMigration`).

The change before that (version 4) was the meaning of `groups` in sessions: it used to record "collapsed groups" and now records "groups the user clicked into the opposite of their
default state". Conflicts / staged / unstaged are expanded by default and stashes collapsed by default (`groupOpenByDefault`), so
containing `"stash"` means "stashes are expanded". When reading a version 3 file, `"stash"` is removed from `groups`.

Untracked files used to be a separate group (key `"untracked"`) and are now merged into unstaged (`GroupKey(git.Untracked)` is
`"unstaged"`); `"untracked"` in old files is thrown away on read (`groupKeys` doesn't recognize it), without bumping the version.

**Older formats** are handled by `workspace.migratePanels`: the `panels` table of version 1, the even older four-element bool
array, and the even older `repos.json`; top-level `added` / `hidden` are assigned to the first workspace opened. The next save
writes version 5.

#### Shared by several windows

All windows share one state.json, each saving its session through `workspace.Store`. Nothing is written when the content hasn't
changed (`Store.Save` compares with the bytes it last wrote).
