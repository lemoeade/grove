# Grove 需求定稿

2026-11-08。来源：`agent-vcs-design-notes.md`（仓库外的设计笔记，一至四）、Grove v0.18.9 现状（[README](../README.md)、[architecture.md](architecture.md)）、11-08 定位讨论。本文决定做什么、不做什么、先做什么；机制细节以设计笔记为准，两者冲突时以本文为准。

## 0. 一句话

Grove 是架在 git 上的 agent 版本控制系统，加上人的决策面。类比：jj 之于 git。

## 1. 定位

- 对象不变：一个窗口，所有仓库，变更与 diff，终端，低内存。
- 主语变了：从「我的改动」变成「所有写者的改动，和我的决定」。你的工作树里大部分改动是几个 agent 会话同时写的，工作台要回答的是谁改了什么、在不在说好的范围里、验证过没有、和别人撞没撞、能不能落地。
- 边界：记录事实，呈现给人做决定。机器的决定（任务派给谁、租约撞上是等还是继续、风险阈值、抽样比例）留给 harness 和策略，Grove 不做编排，不做 harness。
- 用户与场景：一个人，一个工作区五个仓库，Claude Code 与 Codex 同时若干会话，macOS Apple Silicon。
- 今天空着的位置：本地、macOS 原生、多仓库、不绑 harness、低内存。Codex app 是单 harness，DSH History 绑 LayerFS 只在 Linux 内核，Claude Code 桌面端是「当前会话加切换器」，Cursor 加 Graphite 走 GitHub 的 stacked PR。

## 2. 原则

按序排列，冲突时前者优先。

- P1 所有仓库、所有写者同时可见。禁止任何「当前 X 加切换器」的视图，X 是仓库也是会话。
- P2 真相在 git 对象库里。Grove 的每个对象都是 git 对象，普通 git 客户端读得到字节；对外永远导出普通 commit；没有强制推送，撤回是一条新操作。
- P3 窗口关着记录不断。记录由守护进程产生，窗口只是它的一个客户端。
- P4 不绑 harness。有 hook 的归属到调用；没有 hook 的至少归属到写者和时间。
- P5 记录事实不做决定。机器策略留给 harness 和编排；人的决定在窗口里做。
- P6 由你决定何时修改，不主动上传（沿用 README）。守护进程对用户的 index、工作树、分支只读，只写自己的 refs 与对象；不连远程。
- P7 transcript 不出存储。对外只有哈希和过了密钥扫描的摘要。
- P8 测量先于强制。scope 等先记录不拦，拦截点逐条列出（见 B2），拦截必须给出理由。
- P9 每一步独立可用。只靠 git 加 hook 就有用，不等 jj，不等任何新存储。
- P10 资源预算是需求的一部分（见第 6 节）。

## 3. 范围

**3.1 做，三层。**

- A 存储与守护进程：VCS 本体。
- B CLI 与接入：hook、脚本、agent 的读接口。
- C 决策面：窗口。

**3.2 不做，明确列出。**

- 编排：派任务、租约策略、风险阈值、抽样比例、污染等级的顺序。
- harness 本身。
- 服务器、多机、云同步。
- 自有文件系统或自有对象库（不做 LayerFS 一类）。
- LSP、补全、跳转定义（现状不变）。
- 合并队列作为机制。笔记标 待议，先做成可配置的落地策略（见第 8 节）。
- 重写 git 协议或后端。
- 自动更新、插件系统（现状不变）。

**3.3 现有功能全部保留**（README 功能表），其中换角色的四样：

- 暂存区：退到你自己手改时用，不再是改动的中心单位。
- 工作树工位（七种状态、「需要你」条）：升级为会话与写者模型的一部分，状态来源从终端推断扩到 hook 事实。
- 本地历史（每次保存一个快照）：并入 trace 层，人在 Grove 里保存是一类写者。
- Co-Authored-By 识别与「只看 agent 写的」：并入写者归属，扩成按写者过滤。

## 4. 概念与对象

**4.1 写者。** 会话（harness 会话，有 session id）、人（Grove 内编辑与保存）、外部进程（其他编辑器、formatter、watcher、其他工具）、未归属。推断出来的归属要标明推断。

**4.2 两层历史。** trace 层：自动生成、永不改写、按保留期压缩，不进用户分支。change 层：给人审、往主干合，就是 git 的 commit 与分支。两层叠在同一张历史里。

**4.3 对象。** 括号是进入的阶段，见第 7 节。

- 快照（1）：内容寻址的树加写者、时间、触发 id、仓库与工作树；环境指纹（依赖、工具链、迁移、生成器版本）后补（4）。每次写自动产生，没有 staging area。
- 工作区（1）：今天就是 git worktree，一个 agent 一个；fork 连构建缓存和数据分支一起 fork 是目标，不是阶段 1。
- 操作日志（2）：追加、可撤销（含撤销本身），记谁、哪个会话、凭什么能力。
- Change（2 基础，4 完整）：change_id 稳定且跨仓库；parents、快照、意图、scope、provenance、证明、决策记录；多候选（尝试树），落选归档不删。
- 读集与使用集（3）：符号级，三份哈希（签名、函数体、文档注释，格式化和普通注释归一化掉）。
- 冲突（4）：{base, sides[]} 存进 Change，同时生成任务；无关部分不阻塞。
- 证明（4）：{snapshot_hash, check, result, env_hash, signer, 选择方式, 映射版本}，签名者是独立运行器。
- 决策记录（4）：系统填的字段加 agent 自述，落地时强制生成，进仓库永久保留，过密钥扫描。
- 落地集（4）：跨仓库一组 Change 一起落地。
- 否定知识（5）：以 scope 为键，绑定 base 快照与环境哈希。

**4.4 存放约定。** trace 入口在 refs/agent/<session>/ 下，元数据放对象里，ref 只做入口不承载状态；scope 声明在工作树外（git rev-parse --git-path agent-scope/<session>）；trace 按保留期清理；transcript 不入库；决策记录永久。

## 5. 功能需求

### 5.A 存储与守护进程

- A1 守护进程常驻：登录时启动或首次调用拉起，窗口关着照常工作；同一台机一个实例；崩溃后重启从 refs 续接。模式可沿用现有终端后台进程 termd。
- A2 快照两种触发。hook 触发：可写工具调用前后各一次（双快照），Read、Grep、Glob、WebFetch 不拍。常驻触发：watch 层的目录级提示，之后对变动文件增量算哈希、构建树，合并窗口沿用 300 ms，持续变化时最多 1 s。两者并存时 hook 覆盖的时段以 hook 快照为准，常驻快照只补空档。无变化不记。现有 watch 层只给目录提示、不算哈希，增量哈希与建树是新工作。
- A3 归属规则：调用期间的变化归本次调用；两次调用之间的归外部，保留为 external 条目；调用期间没碰的文件归未归属；人在 Grove 内保存的归人；没有 hook 的会话（Codex），若终端前台进程在 agent 名单里且落在某个工作树，归到「该工作树的 agent 会话」并标推断，否则归外部。
- A4 快照成本预算：最大仓库（约 1.2 万文件）一次可写调用的双快照合计不超过 100 ms；常驻快照单次目标个位数毫秒，与变动文件数成比例；首次全量允许 2 到 3 秒，放会话开始。笔记第 0 组实测 git 方案单次 65 ms，双快照 130 ms 超预算，所以要么只拍可写工具，要么守护进程做增量哈希，两者都要。
- A5 scope：声明文件或符号级；每次快照记录 scope 文件的哈希和内容；修订顺序从快照序列算出（先修订再碰是正常规划，碰了再补要审）；修订必须写理由；缩小 scope 记为放弃；拒绝根通配和覆盖大部分已跟踪文件的声明；记录 scope 精度（实际碰到的文件数除以声明覆盖的文件数）和越界率。
- A6 越界检测：hunk 级，键是会话、快照、hunk 哈希（路径加归一化内容，不含行号）；越界 hunk 列表随快照存；受保护 scope 分级标记：删除或跳过已有测试、改预期值、改 golden、调低阈值、改 CI 和 lint 配置；新增测试走正常通道。
- A7 读集与使用集：来源是 harness 观测（Read 范围、Grep 命中、Bash 命令解析）加静态使用集（tree-sitter 名字级，不支持的语言退回文件级并降权）。Bash 命令解析用真正的 shell 解析器，解析不了的计为未知读。维护反向索引：谁的飞行中变更引用了某符号。同一索引四用：过期假设、影响范围、撤销安全、选测试。
- A8 Change：change_id 跨仓库稳定；意图、scope、provenance 从阶段 2 起；候选、证明、决策记录、落地集阶段 4。落地集按依赖顺序推，提供方先，全部验证通过才合。
- A9 操作日志：追加、可撤销，含撤销本身；没有强制推送，撤回是新操作；记录谁、会话、能力。
- A10 冲突：{base, sides[]} 存进 Change 并生成任务；无关部分不阻塞；解决者拿到双方意图与决策记录；三级处理：语法树结构合并只用于低风险场景（import 列表、各自新增的声明），语义冲突派解决冲突的 agent，解决不了的挂起为一等冲突；生成物按「合并源头、重新生成」，lockfile 保留两边钉住的版本、同一依赖钉到不同版本是真冲突；历史解法共享。
- A11 证明：agent 不能给自己签，也不能自己挑检查，检查集由策略定；默认按不密闭处理，密闭靠沙箱（断网、固定时钟和随机种子），只有密闭的按 (snapshot_hash, env_hash) 永久缓存，其余带过期时间和 flaky 统计；准入写成对证明的谓词；「最近的全绿状态」是原生查询；子集验证的绿弱于全量。
- A12 决策记录：系统字段（试过的候选及其证明结果、越界 hunk、碰了哪些受保护检查、假设 = 读集与使用集的交集）加 agent 自述（选择理由、已知风险，标明自述，带 transcript 哈希）；落地时强制生成；过密钥扫描；永久保留。blame 由此有两个答案：哪个决定永远能答，哪一步推理在 transcript 保质期内能答。
- A13 过期假设校验：落地时，base 之后已落地的变更若改了读集或使用集中的符号，不阻塞地做三件事：重跑验证、把对方意图和决策记录推给 agent 问假设是否成立（会话已结束则由校验 agent 读决策记录回答）、审阅时标「基于过期假设」。开工时查反向索引。信号强弱：签名变最强，其次是覆盖该符号的测试断言变，再次是文档注释变和函数体变；读过且使用的最强，只读不用的弱。
- A14 否定知识：以 scope 为检索键；绑定当时的 base 快照和环境哈希，过期就标记；有证据的失败强，判断性放弃弱；带模型版本和投入步数，换强模型后旧失败整体打折但不删除；带可续跑的快照。
- A15 环境指纹进快照：依赖、工具链、迁移、生成器版本；阶段 4 起，先从 lockfile 与工具链版本哈希开始。
- A16 保留与清理：trace 按保留期压缩清理，磁盘有上限（保留期与大小可配置）；transcript 不存，只存哈希；决策记录永久；清理只删 refs/agent 下的入口和不可达对象，不碰用户对象。
- A17 能力模型（目标）：agent 只写自己工作区和自己名下的 Change；历史只追加；删除一律归档；快照时扫描密钥。macOS 单机上 agent 进程与用户同权限，前提 1 的沙箱条件今天不成立，先做只追加和密钥扫描，其余列入第 8 节。

### 5.B CLI 与接入

- B1 CLI：会话开始、快照前、快照后、scope 声明与修订、读集观测、落地等子命令；输出结构化、无交互；写操作带 op id 幂等；给 hook 和脚本用，窗口不依赖它。
- B2 Claude Code 接入：SessionStart 建每会话 index 并拍第 0 个快照；PreToolUse 与 PostToolUse 只对可写工具（Bash、Write、Edit、NotebookEdit、MCP 工具）。拦截点只有两处：PreToolUse 拦第一次 Write 或 Edit，没有 scope 声明就拒绝并要求先声明；Bash 写入只能事后发现，快照 diff 非空且无声明时在 PostToolUse 要求补，记为碰了再补。修订只记不拦。commit message 放 session_id、tool_name、file_path、tool_use_id，不放 prompt。trace 的 diff 只在相邻快照之间算，不拿 HEAD 当基线。
- B3 Codex 接入：没有逐调用 hook，走常驻快照与工位推断（A3）；会话边界取终端前台进程的起止；全部标推断。
- B4 agent 读接口（阶段 3 基础查询，阶段 5 完整）：按 token 预算的 diff，带 since、budget、exclude，按相关度排序，超预算自动摘要；「自我上次看过以来我 scope 内被谁改了」是原生查询；blame 指向决定和推理步；一门 revset 式查询语言。
- B5 外部平台上的写入以导入方式进存储，成为人类署名的普通 Change；禁止对称同步。
- B6 导出与兼容：对外永远是普通 git commit；trace 不进用户分支；不碰用户 index 与工作区（沿用 GIT_OPTIONAL_LOCKS=0 的只读刷新）；并发写自己的 index 加锁。

### 5.C 决策面（窗口）

- C1 写者维度：Git 栏与变更列表按仓库 × 写者组织；会话列表显示每个活动会话在哪个仓库、工作树、终端，状态沿用等你、运行中、空闲；禁止「当前会话加切换器」。
- C2 会话时间线：一个会话从开始到现在的快照序列；任意两张之间的 diff；每个 hunk 带归属标签（本次调用、外部、未归属、人）、越界标记、受保护标记；hunk 按风险排序，越界和受保护的在最前。
- C3 人工标注：越界 hunk 一键三选，确实越界、合理但没声明、不算越界；键是会话、快照、hunk 哈希；标注进 trace，供测量清单第 2 项。
- C4 两层历史：历史面板在现有 commit 图与合并历史上叠加 trace 层，按会话折叠、按保留期消失；不是每个 agent 一条 lane 的切换视图；「只看 agent 写的」扩成按写者过滤。
- C5 Diff：在 diff 里就地改一行（行为参考 Pierre Diffs 的 Edit mode）；Grove 内的改动归属为人；局部与全文切换保留。
- C6 决定动词：留或弃一个尝试；收或拒一个越界 hunk；解冲突，视图含 base、双方、双方意图与决策记录；落地，跨仓库落地集一次操作，按依赖顺序推；撤回，作为新操作。
- C7 审阅顺序：先决策记录再 diff；hunk 按风险排序；抽样审计的标记（后）。
- C8 「需要你」条扩展：等你的会话、可落地的 Change、挂起的冲突、基于过期假设的变更，上一个下一个在它们之间跳。
- C9 否定知识呈现为「有人试过，结果是这样」（5）。
- C10 不变：单窗口、卡片外观、Phosphor 图标、钢蓝强调色、对话框 C 样式、现有 git 操作（暂存、提交、推送、合并、变基、贮藏、工作树、子模块）、终端、编辑器现有能力、中英文界面。

## 6. 非功能需求

- N1 平台：macOS 13 以上，Apple Silicon；Go 与 mygo；依赖 git 命令行；不需要 Docker，不需要服务器。
- N2 内存：窗口空闲不超过 90 MiB（现 79），全开不超过 130 MiB；守护进程空闲不超过 30 MiB，阶段 1 结束按实测定基线后改为硬指标；trace 索引不常驻全量。
- N3 延迟：A4 的快照预算；窗口空闲 0 帧，trace 不增加空闲重绘；时间线和两张快照之间的 diff 打开不卡顿，具体数字阶段 1 实测后定。
- N4 耐久：对象是 git 对象，落盘语义同 git；守护进程崩溃不丢已写对象，重启续接；A16 的磁盘上限。
- N5 隐私与安全：P7；快照时密钥扫描；决策记录过扫描；不连远程；agent 不拿推送凭据是目标（A17）。
- N6 兼容：普通 git 客户端照常使用；不改用户 index、工作树、分支；git worktree 照常；将来 jj colocated 不冲突。
- N7 可观测：守护进程日志进 logs/；每次快照记成本，供测量清单；归属推断可追溯到依据。
- N8 测试沿用现状：界面测试在内存中渲染不开窗口；写操作只用临时仓库。

## 7. 阶段与验收

每个阶段独立可用，不等后面的阶段；tag 与 build 归规划。阶段对应笔记的验证顺序：归属，越界，读集，落地校验。

**阶段 1 归属。** A1、A2、A3、A4、A16 基础、B1 基础、B2 的快照部分、B3、C1、C2 的归属部分、C4 的 trace 叠加基础、N2 基线。验收：窗口关着记录不断；三个基准仓库双快照预算达标（约 1.2 万、4 千、700 个文件，和笔记第 0 组测量用的同三个）；测量 1 可报（Bash 调用期间撞上外部改动的频率）；trace 不出现在用户分支，普通 git 不受影响；守护进程内存基线测出。

**阶段 2 越界。** A5、A6、A8 基础（change_id、意图、scope）、A9、B2 的两处拦截、C2 的越界与受保护标记、C3、C8 部分。验收：测量 2 可报（三类标签占比、漂移时序占比、scope 精度）；过宽声明被拒；修订理由被记录。进入阶段 2 前定内核（第 8 节第一条）。

**阶段 4 落地。** A8 完整、A10、A11、A12、A13 落地校验、A15、B5、B6 的落地部分、C5、C6、C7、C8 完整。验收：五个仓库一次落地集落地；证明由独立运行器签；决策记录强制生成并过密钥扫描；冲突作为一等对象挂起不阻塞他人。

**阶段 5 以后。** A14、A17、B4 完整（token 预算、查询语言）、C9、语义操作提示。
